# Project and AI reliability review — 2026-11-09

The review made **zero real OpenAI API requests**. AI tests used fake responses, a dummy key and Laravel's stray-request prevention. The separate MySQL concurrency workers also fake HTTP. Documentation lookups and Composer/npm advisory checks did not use the application's API key. No production database, credentials or deployed services were changed.

The code is better guarded after the fixes below, but this review is not a blanket production certification. Model accuracy, grading fairness, actual provider access, live hosting configuration and recovery operations were not validated by making real requests.

## Confirmed problems and targeted fixes

| Problem | Evidence / root cause | Change |
| --- | --- | --- |
| Malformed Q&A output could consume the learner's allowance | A missing `found` defaulted to true; string `"false"` and numeric answers were also accepted. A regression test received HTTP 200 instead of 503. | Require a string answer and a real boolean `found`. Invalid output follows the existing error/refund path and is not recorded as an answer. |
| Malformed login/registration emails caused HTTP 500 | `prepareForValidation()` cast an array to a string before the string validator could reject it. Reproduced with debug disabled. | Normalize only strings; other types reach ordinary validation and return 422. Valid mixed-case registration/login still works. |
| Malformed upload title caused HTTP 500 | An array was passed to the importer's `?string` parameter. Reproduced with debug disabled. | Reject non-string, non-null titles before import with an Armenian error. |
| Nested SCORM launch fallback rejected a usable package | Fallback `pkg/story.html` already contained the archive path, but the manifest directory was prepended again. | Resolve manifest hrefs relative to the manifest; retain archive-relative fallback paths. Existing path containment checks remain in place. |
| Docker ignored two AI configuration overrides | PHP reads `OPENAI_QA_REASONING_EFFORT` and `AI_FULL_TEXT_MAX_TOKENS`, but neither Compose file forwarded them and real `.env` files are excluded from images. | Forward both variables in local/production Compose, keeping current defaults; document them in example environments. |
| Operational documentation described obsolete AI behavior | It claimed sequential evaluation, skipped grading for flagged answers, no retries and a local fallback. Current code does parallel calls, bounded retries and no local fallback. | Correct the README and assignment documentation to match execution and billing behavior. |

The base test case now blocks unexpected HTTP requests for **all** feature tests and overrides the configured key. Previously that protection was installed only by the two AI test classes.

## Reviewed and intentionally preserved

- **Q&A context:** available course ID resolves to its numbered TXT source. Whole cleaned text is used up to the configured estimate; larger texts use Armenian-aware keyword ranking. Course isolation is covered by tests. The displayed chat retains per-course messages, but only the current question is sent upstream; follow-ups must be self-contained. Keeping history out of requests reduces tokens and cross-course contamination.
- **TXT cache:** a request-scoped repository shares reads; persistent entries contain cleaned text, estimated tokens and chunks. Version, filename, size and mtime invalidate entries; deleted sources stop being used. There is an explicit rebuild command. Existing tests cover reuse, file edits, removal, course isolation and estimates.
- **Quota:** the 10-question lifetime limit is enforced by a conditional database increment, not a read-then-write counter. Ordinary failures and `found=false` release the reservation. Unanswerable upstream results are still recorded for usage. Rate limits separately constrain repeated unpaid-to-the-learner attempts.
- **Assignments:** server-owned question and source selection cannot be replaced by posted values. Answer validation precedes API use. Rubric points are validated as integers within 35/30/25/10 bounds and summed server-side into 1–100. Invalid/insufficient grading results fail instead of inventing a grade. Detection evidence must quote the submitted answer. Failed rows have no final score and are excluded from completed history.
- **Concurrency and history:** short MySQL transactions lock the user during assignment reservation; unique hashes reuse completed submissions; leases permit retries and ownership tokens prevent stale overwrites. History is user-scoped and uses bounded cursor pagination. The real two-process race test passed on isolated MySQL.
- **Integration:** developer instructions and stable context precede user data; strict JSON schemas, explicit prompt cache boundaries, `store=false`, timeouts and bounded retries remain. The current model supports the configured reasoning levels and structured outputs. See official [GPT-6 Luna documentation](https://developers.openai.com/api/docs/models/gpt-6-luna) and [prompt caching documentation](https://developers.openai.com/api/docs/guides/prompt-caching). Documentation compatibility does not verify account/model access or actual cache hits.
- **Authentication/security:** session regeneration, password hashing, login throttling, CSRF middleware on session APIs, authenticated course-file routes, production upload-token enforcement, archive limits/path checks and realpath containment were reviewed. Nginx's course alias remains internal and only `index.php` executes as PHP. Model text is inserted through `textContent`; Blade output is escaped. No API key is sent in the frontend payload.
- **Database/architecture:** migrations, foreign keys, assignment uniqueness/processing/history indexes, eager loading for the legacy course API, seeders, error rendering and deployment/backup scripts were reviewed. No database schema, grading prompt/policy, UI, localStorage key or dependency version changed.
- **Frontend:** course switching, pending AI answers, separate assignment drafts, busy controls, history response guards, CSRF headers, session-expiry handling and request timeouts were inspected. Browser interaction with AI controls was intentionally avoided.

## Remaining concerns and recommendations

1. **High — grading policy:** heuristic AI-authorship estimates at or above the threshold still assign zero and discard the grade. Quoted indicators and schema checks do not establish authorship. Prompt injection defenses are instructions, not a guarantee that a model will grade correctly. Preserve the requested policy for now, but require human review and representative Armenian evaluation before consequential educational use. Mocked tests establish control flow, not fairness or answer truth.
2. **Medium — Q&A retry/crash semantics:** the frontend prevents ordinary double submission, but there is no server-side idempotency key. Duplicate POSTs across tabs or after a lost response can consume two questions and make two paid calls. A killed worker after reservation can leave a question consumed without a recorded answer. Fixing this properly needs durable request/reservation identity and recovery; an ad hoc counter adjustment or cache lock was intentionally avoided.
3. **Medium — billing completeness:** stored input/cached-input/output counts are useful successful-result telemetry, not an invoice ledger. Invalid outputs, one successful parallel call followed by another failing, and interrupted attempts can incur usage without saved totals. Q&A rows do not retain the model used; cache-write token details and monetary costs are not recorded. Add per-attempt accounting only with an explicit retention/schema design. Current cache billing distinguishes cache writes as well as reads; a simple cached/uncached split is insufficient for exact cost reconstruction. See [official cache cost accounting](https://developers.openai.com/api/docs/guides/prompt-caching).
4. **Medium — cost policy:** grading and detection both run even when detection will discard the grade. This is an intentional latency/cost tradeoff, left unchanged. The 16,000-token output ceiling applies to each call, including reasoning. Public signup allows multiple accounts, so per-account limits are not a global budget ceiling. Review enrollment controls and provider/project spend controls before broad public access.
5. **Operational — cache/retrieval:** same-size source edits with preserved mtimes need an explicit rebuild. Concurrent cold misses can duplicate chunking work. Oversized-source keyword retrieval can miss synonyms or foreign-language questions. These are bounded/documented tradeoffs; no new cache architecture or retrieval provider was introduced.
6. **Operational — production readiness:** repository deployment notes describe a historical HTTP/IP setup, a past invalid-key response, and backups remaining on the VPS. Their current live status was not verified. Confirm HTTPS, secure cookies, off-server backups, restore procedures and current provider access separately. Do not infer current key validity from the historical notes.
7. **Existing scope limits:** sources for courses 1, 2, 7 and 11 are absent, so AI is unavailable for them. Learner progress is browser-local and shared by accounts using that browser/origin; do not rename its keys. Certificates remain the explicitly requested static presentation view. The legacy recommendations endpoint also trusts nested client progress values more than the AI endpoints; validate its numeric input contract before exposing it to new clients.
